# brockhoff_context (Data Source)

Generates standardized naming conventions and cloud-provider-specific tags for infrastructure resources.

## Example Usage

```terraform
data "brockhoff_context" "example" {
  namespace        = "myorg"
  name             = "myapp"
  environment      = "prod"
  environment_name = "Production"
  environment_type = "Production"
}

# Use the computed outputs
resource "aws_s3_bucket" "example" {
  bucket = data.brockhoff_context.example.name_prefix

  tags = data.brockhoff_context.example.tags
}
```

## Environment Type

`environment_type` classifies the deployment stage so that consuming configurations can choose
resource defaults suited to it. Resiliency defaults follow the RPO and RTO targets below, and
cost-optimization defaults focus on shutting resources down outside working hours. The provider
validates and passes the value through `context_output`; applying the defaults is the consuming
configuration's job. It does not affect `name_prefix` and is not emitted as a tag. Its only
effect on outputs is that `Ephemeral` sets the deletion date to today (UTC) plus 90 days when no
`deletion_date` is supplied.

| Type | Use case | Configuration focus | RPO | RTO |
|------|----------|---------------------|-----|-----|
| `None` | Custom configuration | No defaults applied; use individual config values | N/A | N/A |
| `Ephemeral` | Temporary environments | Cost-optimized, minimal durability requirements | N/A | 48h |
| `Development` | Developer workspaces | Balanced cost and functionality for active development | 24h | 48h |
| `Testing` | Automated testing | Consistent, repeatable configurations | 24h | 48h |
| `UAT` | User acceptance testing | Production-like settings with some cost optimization | 12h | 24h |
| `Production` | Live systems | High availability, durability and performance | 1h | 4h |
| `MissionCritical` | Critical production | Maximum reliability, redundancy and monitoring | 5m | 1h |

## Generated Tags

Resource tags (`tags`), each key prefixed with the provider's `tag_prefix`:

| Key | Emitted |
|-----|---------|
| `environment` | Always: `environment_name`, else `environment`, else `dev` |
| `availability`, `managedby` | Always (defaults `preemptable`, `terraform`) |
| `deletiondate` | Always: `deletion_date`, else today + 90 days for `Ephemeral`, else `never` |
| `costcenter`, `securityreview`, `privacyreview` | When set, otherwise the cloud's N/A value if `not_applicable_enabled` |
| `productowners`, `codeowners` | When `owner_tags_enabled`; the value or N/A as above |
| `projectmgmtid`, `systemid`, `componentid`, `instanceid` | Only when the identifier is set; prefixed with the platform when `system_prefixes_enabled` |
| `sourcerepo`, `sourcecommit` | When `source_repo_tags_enabled` and git information is available; the URL never contains credentials |

Data tags (`data_tags`):

| Key | Emitted |
|-----|---------|
| `sensitivity` | Always (default `confidential`) |
| `dataregulations` | The joined list, or N/A if `not_applicable_enabled` |
| `dataowners` | When `owner_tags_enabled`; the joined list, or N/A as above |
| `sovereignty` | Only when `data_sovereignty` is set; never N/A |

`additional_tags` and `additional_data_tags` are merged last and override generated keys. Every
value is sanitized and truncated for the target cloud, and tag keys that are invalid for the
target cloud are rejected.

## Migrating from terraform-external-context

The data source produces the same outputs as the `kbrockhoff/terraform-external-context` module,
with these deliberate differences:

- `cloud_provider` and `tag_prefix` are set once on the provider, not per context, and the
  default `tag_prefix` is `bc-` rather than empty.
- When only one of `namespace` or `environment` is set, `name_prefix` joins the parts that are
  present (for example `ns-app`); the module used `name` alone. This can rename resources.
- `name` is never inherited from `parent_context`.
- Tag keys that are invalid for the target cloud (for example uppercase keys on `gcp`) are
  rejected instead of being passed through.
- `data_sovereignty` and its `sovereignty` data tag are new.
